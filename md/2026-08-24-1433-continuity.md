## What Phase 2 decided, so it is not relitigated

| | |
|---|---|
| Pseudo-projects | Stored (the sidebar wants Favorites), excluded by `ProjectFilter::default()` (a write-target picker must not offer them) |
| A project's views | An empty `views` from a listing means "not loaded", never "none" — only `set_project_views` honours empty. Fetched on demand, not in every pull |
| Label ownership | Stored (`labels.created_by_id`, migration v2). Vikunja only lets a label's creator edit it |
| Created tasks | Get a provisional **negative** id immediately; `settle_create` swaps in the server's row and retargets whatever was queued behind it |
| Undo | The inverse of a `Mutation`, queued like any other change. Not a parallel mechanism. Undoing a delete *re-creates* — Vikunja has no undelete |
| Labels vs assignees on a write | Assignees are the task body (`UpdateTask` carries them); labels get their own endpoints, and the engine attaches/detaches them itself, including on create |
| A failed push | Stops the queue. It is ordered, and later entries assume earlier ones landed |
| A 4xx | Final: roll back, and take everything queued behind it *for that task* — those were built on a state the server refused |
| An unreadable response | Treated as transient. It may mean the write landed; a duplicate task is an annoyance, a lost one is a bug report |
| A pull | Never overwrites or deletes a task with unsent local changes. Both have a test that fails without the guard |

## The one premise that is not yet verified live

`Sync::pull` stores what `GET /tasks` returns and then deletes every local task the
listing did not mention. If the server quietly omits **done** tasks from an unfiltered
listing, one pull erases the user's completed history. The spec says "Returns all tasks
on any project the user has access to" and the known filtering is on *views*, not the
plain endpoint — but that is an inference, and this repo settles those with experiments.

`criax-api/tests/live.rs::an_unfiltered_task_listing_includes_done_tasks` is the
experiment: it asks for `done = true` explicitly and asserts the unfiltered listing
already contained those ids. It reports "inconclusive" and passes if dev has no completed
tasks, so **complete a task on dev before running it**.

```sh
./run-live-tests-token.sh          # or ./run-live-tests-password.sh admin
```

Both prompt for the credential with `read -s`. `tests/live.rs` takes an allow-list: the
URL must match `CRIAX_DEV_HOST`, and prod is refused with no variable that can countermand
it. `connect()` sweeps leftover fixtures before every test, so **each live run writes to
dev even before its assertions**.
