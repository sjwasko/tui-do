## The five things in Phase 3 that are load-bearing

Undo any of these by accident and the symptom will be baffling.

| | |
|---|---|
| **Query correlation** | Every `Effect::LoadTasks` carries a `QueryId`; an answer whose id is no longer current is *dropped*. Holding `j` down the sidebar issues a query per project and the slowest would otherwise win. `an_answer_to_a_superseded_query_is_dropped` |
| **Selection is a `TaskId`** | Never a row index. A sync that reorders or drops rows must not move the cursor onto a different task. `the_selection_follows_the_task_not_the_row` |
| **Panes are tri-state** | `Auto | Shown | Hidden`. A resize re-evaluates only panes still on `Auto`, so toggling one pins it. A pinned pane still yields below its hard minimum |
| **Modals are exclusive** | The top of the stack takes every key except `Ctrl-C`. No fall-through. `a_modal_swallows_every_key_except_quit` |
| **One keymap table** | `KEYMAP` is read by `update`, rendered by the help modal, *and* enumerated by the `:` command palette, so none of the three can drift. Adding a binding is a row, not a match arm |

## The width rule, because it will look wrong

`rows::measure` does **not** grow capped columns to their maximum first, even though
`COLUMN_LAYOUTS.md` reads that way and it is the obvious implementation. That rule hands
the labels twenty columns on a 110-wide terminal while the title stays at its minimum and
wraps to three lines. What ships: every column that can still grow grows by the same
amount, and what a capped column cannot take falls to the title. Both the documented
worked example and the narrow case come out right, and both are tested.

## Deliberate omissions someone will mistake for bugs

- **`view.default_filter` is read and ignored.** It holds a Vikunja filter expression;
  the local store answers a title substring. Wiring one to the other returns nothing at
  all. Filter expressions arrive with saved filters in Phase 6.
- **`:` runs a command by name**, listing the keymap with each binding's key beside it.
  Motions and the palette itself are excluded (`Action::is_command`). A command chosen by
  name takes the same code path as its key.
- **The `Table` and `Kanban` tabs draw but do nothing.** Phase 6 is the views API; the
  strip exists from Phase 3 so they land in a place rather than a redesign.
- **The preview pane is a summary, not the task.** Descriptions are HTML from the web
  editor and are shown as stored. Phase 5 pipes them through `glow` with a
  `pulldown-cmark` fallback, and adds `Screen::Task` for comments and attachments.
- **No writes.** Phase 3 is read-only by design; `Effect` is `non_exhaustive` and the
  runtime logs an unknown effect rather than dropping it silently, so Phase 4 adds write
  effects without touching this crate's shape.

## What the review changed, and why it is worth reading

`/code-review` on the description stripper found seven things, and the dev instance's own
487 non-empty descriptions settled which of them were real:

| finding | in the real data |
|---|---|
| `<` + a letter treated as a tag eats prose | **Confirmed, and worse than reported.** `<http://Www.ftc.gov>`, `<mailto:usarmy…>` and `CAM_<CAMERA_MAC>_NAME` are all real descriptions there, and the heuristic deleted each up to the next `>` — losing two URLs outright |
| numeric entities undecoded | Confirmed, though not the example given: the dev instance stores `&#x27;`, and zero `&#34;` |
| `td`/`th` missing, cells run together | 3 descriptions carry tables |
| pretty-printed markup doubles the paragraph gap | Real: `</p>\n<p>` and `</p><p>` rendered differently |
| `<script>` / `<style>` / comments shown as text | Zero occurrences — the sanitiser strips them — but `plain_text` is `pub`, so it is handled |
| per-paragraph line cap is no cap | Real: bounded now by what the pane can show |
| `<pre>` loses indentation | Real, and **accepted**: HTML whitespace collapsing is the model, and code blocks are Phase 5's job |

**366 of the 487 descriptions contain no tag at all.** That is the fact that decides the
design: this function runs mostly over prose, so "anything that looks like a tag" is the
wrong default and an allowlist of real HTML element names is the right one. A tag also has
to *end* like a tag — `<pre-release plan>` is not a `<pre>` — and text that opens a tag and
never closes it stays text rather than eating the rest of the description.

Verified by running the stripper over all 487: none left markup behind, and the 68 that
shrank sharply are links, where the `href` goes and the text stays.
