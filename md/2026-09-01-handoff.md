## What driving it found, and why that matters

**Every serious bug in the last two days came from using the program, not from reading it.**
Seven parallel reviewers produced one Critical and fourteen Importants; the two that
actually destroyed or duplicated data were among them but *mis-scoped*, and the worst one was
filed as "unverified". Hand-driving found:

- **BUG-3** — quitting mid-push created a second task. Reproduced by pausing the dev
  container. `CreateTask` had **no** replay guard at all, where the review said the guard was
  merely skipped.
- **BUG-15** — every full pull deleted the tasks of archived projects. Confirmed against dev:
  the server had four, the store had none, and an unfiltered `GET /tasks` omits them. This
  was the *second half* of a bug whose first half had been fixed months earlier; `CLAUDE.md`
  said the fix "covers `/projects` only", and that sentence was the bug.
- **BUG-17** — archiving the project you are viewing wedged the sidebar completely. Only
  visible *because* BUG-15 was fixed that morning.

The lesson worth keeping: **a test that mocks the premise proves the handling and not the
premise.** `an_archived_project_and_its_tasks_survive_a_pull` passed for a year while the
behaviour it described was false.

## Things that will bite

**Read the test total, not the last line.** `cargo test --workspace` prints eighteen
`test result:` lines and the last five are doc-test targets with no tests, so a completely
green run ends with `0 passed`. Sum them:

```sh
cargo test --workspace 2>&1 | grep -E '^test result' | \
  awk '{p+=$4; f+=$6} END {print "passed="p"  failed="f}'
```

**695 passing, 0 failing, 0 ignored** as of this handoff. Clippy clean under `-D warnings`.

**`~/.local/bin/tui-do` is a symlink to `target/release/tui-do`.** Build `--release` before
handing over a fix or the user retests the old binary.

**A toast can be cut off mid-sentence** — BUG-16, and it is the most expensive open bug
measured in human time rather than data. It has caused **two** misdiagnoses in two days: it
hid *"not authorized: missing, malformed, expired…"* (a prod token on a dev box) and
*"Copied … — no display on this box"* (correct behaviour that read as broken). Fixing it is
about twenty minutes: let a toast take a second row when it does not fit.

**Test fixtures that echo something other than what was sent are not harmless.** A mock
returning a hardcoded title renamed the task under the cursor and made a correct fix look
broken. Five separate times in two days something looked verified and was not — including a
"fresh environment" test that silently used the real store because `XDG_DATA_HOME` was set.

## Publication

The README was rewritten for someone who has never seen the source, and then fixed again
after it stalled a real install: the clone line was a literal `<this repository>`, the build
prerequisites were missing entirely (`rusqlite` is bundled, so SQLite compiles from C and a
toolchain is mandatory), and nothing said there is no first-run wizard. It now carries
install, config, the key map, quick-add syntax, how to read the test output, and an honest
"what is not there yet".

`Table` and `Kanban` in the header now say `(soon)` **in the text**, because the dimming that
carried that meaning is `muted()`, which resolves to `Color::Reset` at `ColorDepth::None` —
identical to `text()`. There is deliberately no way to focus them: a tab stop whose only
destination is a coming-soon notice is navigation to a dead end.
