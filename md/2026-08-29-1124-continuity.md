## The five questions the design document has to settle

1. **`glow` is a subprocess, so it is an `Effect`.** Rule 1 says the render loop never
   awaits I/O and shelling out is I/O, so the renderer cannot be called from `view`. That
   forces a cache keyed by (task id, width) in the model, a `Msg` carrying the rendered
   result, and a decision about what to draw while it is still rendering — `plain_text`
   already produces something reasonable, so "render the plain form immediately and swap
   in the rich one when it arrives" is available and worth considering.
2. **Does `Enter` open the detail screen?** It is `OpenTask` today, which shows the preview
   and moves focus to it. The detail screen is the second `Screen` variant, so this is the
   moment to decide whether `Enter` still means "focus the preview" or now means "open the
   task".
3. **Relations** — cria has them half-built and disabled. `PLAN.md` says properly or not at
   all. Note that `Task::related_tasks` already deserializes, so the read side is nearly
   free; the write side is `TASK_RELATION` with a `relationKind` in the path.
4. **Terminal image preview** is a capability question (kitty graphics, sixel, neither) and
   belongs behind the same platform trait as URL opening and the clipboard.
5. **`tui-do doctor` does not exist** and `PLAN.md` leans on it as the thing that reports
   which markdown renderer is active and how to install `glow`. Build it or reword the
   plan.

## Things Phase 5 will hit that are already known

- **Attachments write files to disk and `glow` is a subprocess.** `PLAN.md`'s gate list
  says to run `/security-review` after Phase 5 for exactly these two reasons.
- **`glow` is in the Arch repos and Omarchy but not in Ubuntu 26.04's default set**, which
  is why the fallback exists — not for Windows.
- **A description holding only an embedded image renders blank today.** Recorded in
  `MANUAL-CHECKS.md`; attachments are the phase that fixes it.
- **`POST /tasks/{taskID}/comments/{commentID}` documents no request body but requires

- **Anything new that lists must not assume pagination** (rule 4) and **anything new that
  writes goes through the outbox** (rule 5). Comments and attachments are writes.

# How we got here

## What shipped on 2026-08-28

Eight commits: the three decisions the previous note parked, two defects the manual checks
found, one design document, and shell completions.

**`r` fetches only what changed; `R` fetches everything.** A pull of dev is 78 pages and
15 seconds; the same pull filtered to what changed is one page. `sync::Reach` names the two
and **only `Full` may delete** — a filtered listing does not mention what did not change,
so retaining against it would erase all but the last few days of the user's tasks. Startup
and the timer stay full. What `r` cannot see is a deletion made in another client, so it
names `R` in its toast at the keystroke.

Two things inside that were not in the parked proposal and matter:

- `LAST_PULL` and the new `LAST_RECONCILE` are separate keys. An incremental pull can say
  "everything up to here has been seen" without being able to say "and nothing else is
  gone".
- The watermark is stamped from **before** the requests, and the filter reaches a further
  two minutes back. The watermark is this machine's clock and `updated` is the server's; a
  few seconds of disagreement would drop a task in the gap *permanently*, because the next
  pull asks from an even later point.

**The help modal folds into two columns** when one column would be clipped and the terminal
is wide enough. At 80 columns it goes back to scrolling and says so. The fold only ever
lands on a heading, so no section is cut across the gutter.

**Past dates are said loudly on all four ways in.** This was the B9 failure. The rule was
implemented once, on `D`, and there are four surfaces: `D`, the edit form's Due field,
quick-add, and `tui-do add`. The other three answered "Saved", "Added" and nothing —
exactly the quiet confirmation the rule exists to prevent. `past_due_note` is now the rule
in one place. The edit form warns only when the save *moved* the date and compares **by
day, not by instant**: the field shows a date and the parser gives it 23:59, so an
untouched form re-parses 09:00 into 23:59 and an instant comparison would call every save
of anything overdue a backdate.

**`d` holds its place down a list, the way `x` does.** Reported by hand, became E6. `x`
moves the selection to the row that slid into the gap; `d` queued an `UpdateTask` that
replaced the row in place, left the selection on a task the reload then dropped, and
`TasksLoaded` cannot tell "the selected row left this list" from "this is a different list"
— so it fell back to the first row and every press sent the cursor to the top. Now the row
leaves at the keystroke and the selection steps down. Undo still works: every
`Effect::Apply` is followed by a reload, which is what returns the row.

**Shell completions.** `tui-do completions <bash|zsh|fish>`, generated from the same command
table `--help` is built from. See the environment note below for what it buys here.

## Creating labels: designed, not built

`md/2026-08-28-label-creation-design.md` is the whole of it, and it is **not Phase 5 work** —
it is a Phase 4 gap found after Phase 4 was signed off. Four places in the interface say
"tui-do cannot create labels yet"; the API half is done and live-tested; what is missing is
`Mutation::CreateLabel`, and rule 5 means that variant *is* the write path.

The decision the document exists for: `Mutation::subject()` returns a `TaskId` and
`outbox.subject_id` is an untyped `INTEGER`, load-bearing in five places including the guard
that stops a pull from deleting a task created offline. Provisional task ids count down from
`-1`; a label counter would too, so task `-1` and label `-1` would be the same value in the
same column, and `retain_tasks` and `settle_create` both break silently. Recommended: a
`Subject { Task, Label }` enum and a `subject_kind` column.

**Two decisions are still yours** before it can be built:

1. **Create-only, or the whole lifecycle?** Rename, recolour and delete each need their own
   mutation. Deleting is the one `u` cannot cleanly undo — the label returns with a new id,
   detached from everything it was on.
2. **Should `*newlabel` in quick-add create silently?** Everywhere else the user is looking
   at a label list and asking for a new one. In quick-add they typed a task, and a typo
   becomes a permanent label on the server.

Then three things need measuring against dev, none answerable from `spec/vikunja.json`:
what a duplicate label title does, whether `PUT /labels` with `id: 0` has the
path-versus-body trap, and what a replayed create answers — there is no `is_already_done`
arm for it.

## Environment notes worth not rediscovering

**This workstation runs bash, and only bash.** fish and zsh are not installed. Completions
are installed at `~/.local/share/bash-completion/completions/tui-do` and bash-completion's
lazy loader picks them up. The greyed-out inline suggestion that prompted the work **cannot
happen on bash** — it belongs to fish's autosuggestions or the zsh-autosuggestions plugin.
One loose end: clap generates the spec with `-o bashdefault -o default`, so bash still falls
back to filenames when the function returns nothing, which overrides the `ValueHint::Other`
on the task text. `tui-do add <TAB>` therefore still lists the working directory on bash.

**Do not share `CARGO_TARGET_DIR` with a git worktree.** It bakes the worktree path into the
cached conformance binary as its `CARGO_MANIFEST_DIR`.

**`tui-do add` writes to the real store.** Point a scratch `TUI_DO_CONFIG` at a scratch store
when testing it.

Dev `https://dev-box.example.net:8443` for everything. Prod
`https://prod-box.example.net:8443` **read-only, always** — Forgejo shares that box on a
different port, so pushing git there is not a prod write. **Tailscale has to be up or the
push fails**, which it was not at the start of the last session.

    local  --push-->  Forgejo (origin)  --push mirror, 8h-->  GitHub (private)

There is no `github` remote in this checkout, on purpose.

`~/.local/bin/tui-do` symlinks to `target/release/tui-do`, so **build `--release` before
saying a fix is ready to try**.
